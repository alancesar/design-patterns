# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A bilingual Docusaurus 3 site (a personal design-patterns wiki) published at https://designpatterns.alancesar.dev. It is almost entirely Markdown content; the only code is the Docusaurus config, `sidebars.ts`, one React component (`src/components/CatalogCards`), CSS and a Prism theme. Netlify builds on every push to `main` and makes deploy previews for PRs (`netlify.toml`, Node 22).

## Commands

```bash
npm start              # dev server (pt-BR only; add `-- --locale en` for English)
npm run build          # builds both locales into build/; this is the check that matters
npm run serve          # serve build/ (local search only works here, not in `npm start`)
npm run typecheck      # tsc
```

There are no tests or linters. `npm run build` is the verification step: it fails on broken links and broken Markdown links (`onBrokenLinks: 'throw'`), in both locales.

## Content model

Hierarchy is **domain → catalog → group → pattern**: `docs/<domain>/<catalog>/<group>/<pattern>.md`. Domains are `coding`, `application`, `architecture`, `cloud`, `ai`.

- **Pattern page:** frontmatter `title`, `pattern_slug`, `category` (the group name), `tags`, `source`, `sidebar_label` (quoted), plus `origin` and `also_in` when they apply. The body sections are fixed: Descrição, Problemas que resolve, Quando usar, `### Quando evitar`, Trade-offs (a `| Ganho | Custo / Risco |` table plus bold bullets), Diagrama (Mermaid), Exemplo (optional), Padrões relacionados, Referência. English uses Description, Problems it solves, When to use, `### When to avoid`, Trade-offs (`| Benefit | Cost / Risk |`), Diagram, Example, Related patterns, Reference. Use `docs/coding/gof/creational/builder.md` as a reference.
- **Catalog page** (`docs/<domain>/<catalog>/index.md`): an intro, then per-group tables whose summary column is the first sentence of each pattern's description. Keep these tables in sync when you add or rename patterns.
- **Shared patterns:** a pattern that belongs to several catalogs has a single document, in the catalog that owns it. The other catalogs reference it from `sidebars.ts` with a `link` item (`href: "/<owner path>?catalog=<slug>"`, `className: "sidebar-shared"`, which renders a ★), and the document lists them in `also_in`.
- **Tags** are in English and span groups. Architecture and cloud catalogs use the Well-Architected pillars; GoF and PoEAA use design goals.
- Pattern names, categories, tags and code identifiers stay in English even in the pt-BR text.

## Structure that spans several files

- **`sidebars.ts` is the source of truth** for catalog structure: group order, which patterns are in each group, and shared links. Edit it by hand, and ignore its "Generated by scripts/import-content.mjs" header: that script no longer exists. Keep the object valid JSON (double quotes, no trailing commas, no comments), because tooling parses it as JSON.
- **Home-page cards** come from `src/data/catalogs.json` (`patterns` counts the shared links too). Each English card title is `catalogCards.title.<href>` in `i18n/en/code.json`.
- **Navbar domains, footer catalogs/sources, tagline and copyright** live in `docusaurus.config.ts`. The tagline and copyright switch on `DOCUSAURUS_CURRENT_LOCALE`, so the year stays dynamic. If `npm run write-translations` adds a `copyright` key back to `i18n/en/docusaurus-theme-classic/footer.json`, delete it. Footer and navbar labels for English are in `i18n/en/docusaurus-theme-classic/`.
- The home page (`docs/index.mdx`) and each domain page (`docs/<domain>/index.md`) list catalogs by hand and need updating whenever a catalog is added.

## i18n

pt-BR is the default locale (served at `/`), and English is served at `/en/`. Every page in `docs/` has an English counterpart at the same relative path under `i18n/en/docusaurus-plugin-content-docs/current/`; currently all of them do. A missing English page silently falls back to Portuguese, so check both trees for parity.

- New catalogs and pattern changes go in **both languages in the same PR**. The English version is a faithful translation: same frontmatter, sections, links and code blocks.
- Internal links are always absolute URL paths without `.md` (`/coding/gof/creational/builder`, `/tags/<tag-kebab-case>`). Never use relative `.md` links: they break between a translated and an untranslated page. Docusaurus adds the `/en` prefix itself.
- In Mermaid diagrams, translate only labels, participants, notes and `%%` comments, not node ids or syntax. Don't put HTML in diagrams. Quote `flowchart` labels that contain accents, parentheses or punctuation.
- In code examples, keep identifiers identical across languages and translate only comments and user-facing strings.

## Workflow

- Branch from an up-to-date `main` and open each PR directly against `main`. Don't stack PRs on other feature branches: stacked PRs have stranded content that never reached `main`.
- The repo is public. `.claude/` (including the local `pattern-catalog` skill, which automates adding a catalog) is excluded locally through `.git/info/exclude`, not `.gitignore`. Never commit or push it.
