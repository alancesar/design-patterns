# Enterprise Integration Patterns

Catálogo pessoal baseado nos [Messaging Patterns](https://www.enterpriseintegrationpatterns.com/patterns/messaging/) do site Enterprise Integration Patterns, de Gregor Hohpe e Bobby Woolf, que resume o livro *Enterprise Integration Patterns* (2003). Os Conversation Patterns do site ficam fora do escopo. Cada padrão tem descrição, problemas que resolve, quando usar, trade-offs, etiquetas (pilares do Well-Architected Framework) e um diagrama Mermaid.

Padrões marcados com ★ são compartilhados com outro catálogo: este catálogo aponta para o documento original, revisado com o conteúdo desta fonte.

Total: 65 padrões em 7 grupos. Etiquetas: Pilares do Well-Architected Framework.

## Integration Styles (4) {#integration-styles}

| Padrão | Resumo | Etiquetas |
| --- | --- | --- |
| [File Transfer](/architecture/eip/integration-styles/file-transfer) | Em File Transfer, cada aplicação produz arquivos com as informações que outras aplicações precisam e consome arquivos gerados pelas demais. | [`Cost Optimization`](/tags/cost-optimization) [`Operational Excellence`](/tags/operational-excellence) |
| [Shared Database](/architecture/microservices/service-collaboration/shared-database) ★ | No padrão Shared Database, todos os serviços utilizam um único banco de dados. | [`Reliability`](/tags/reliability) [`Operational Excellence`](/tags/operational-excellence) |
| [Remote Procedure Invocation](/architecture/microservices/communication-styles/remote-procedure-invocation) ★ | Remote Procedure Invocation (RPI) é o estilo de comunicação em que um cliente envia uma requisição a um serviço usando um protocolo síncrono de requisição/resposta, como se estivesse invocando um procedimento remoto. | [`Reliability`](/tags/reliability) [`Performance Efficiency`](/tags/performance-efficiency) [`Operational Excellence`](/tags/operational-excellence) |
| [Messaging](/architecture/microservices/communication-styles/messaging) ★ | No padrão Messaging, os serviços se comunicam trocando mensagens por canais de mensagens, de forma assíncrona. | [`Reliability`](/tags/reliability) [`Performance Efficiency`](/tags/performance-efficiency) [`Operational Excellence`](/tags/operational-excellence) |

## Messaging Channels (10) {#messaging-channels}

| Padrão | Resumo | Etiquetas |
| --- | --- | --- |
| [Message Channel](/architecture/eip/messaging-channels/message-channel) | O Message Channel é o caminho lógico pelo qual duas aplicações trocam mensagens. | [`Reliability`](/tags/reliability) [`Operational Excellence`](/tags/operational-excellence) |
| [Point-to-Point Channel](/architecture/eip/messaging-channels/point-to-point-channel) | O Point-to-Point Channel garante que cada mensagem enviada seja consumida por exatamente um receptor. | [`Reliability`](/tags/reliability) [`Performance Efficiency`](/tags/performance-efficiency) |
| [Publish-Subscribe Channel](/cloud/cloud-design-patterns/messaging/publisher-subscriber) ★ | O padrão Publisher-Subscriber (pub/sub) permite que uma aplicação anuncie eventos de forma assíncrona a vários consumidores interessados, sem conhecer quem são eles. | [`Reliability`](/tags/reliability) [`Security`](/tags/security) [`Cost Optimization`](/tags/cost-optimization) [`Operational Excellence`](/tags/operational-excellence) [`Performance Efficiency`](/tags/performance-efficiency) |
| [Datatype Channel](/architecture/eip/messaging-channels/datatype-channel) | O Datatype Channel dedica um canal a cada tipo de dado. | [`Reliability`](/tags/reliability) [`Operational Excellence`](/tags/operational-excellence) |
| [Invalid Message Channel](/architecture/eip/messaging-channels/invalid-message-channel) | O Invalid Message Channel é um canal separado para onde o receptor desvia as mensagens que recebeu mas não consegue entender ou processar, por exemplo por formato incorreto, campos ausentes ou conteúdo que viola o contrato esperado. | [`Reliability`](/tags/reliability) [`Operational Excellence`](/tags/operational-excellence) |
| [Dead Letter Channel](/architecture/eip/messaging-channels/dead-letter-channel) | O Dead Letter Channel é o destino para onde o sistema de mensageria move uma mensagem que decidiu não poder ou não dever entregar. | [`Reliability`](/tags/reliability) [`Operational Excellence`](/tags/operational-excellence) |
| [Guaranteed Delivery](/architecture/eip/messaging-channels/guaranteed-delivery) | O Guaranteed Delivery faz o sistema de mensageria tornar as mensagens persistentes, de modo que não se percam se o próprio sistema falhar. | [`Reliability`](/tags/reliability) [`Cost Optimization`](/tags/cost-optimization) |
| [Channel Adapter](/architecture/eip/messaging-channels/channel-adapter) | O Channel Adapter conecta uma aplicação que não sabe enviar nem receber mensagens ao sistema de mensageria. | [`Operational Excellence`](/tags/operational-excellence) [`Performance Efficiency`](/tags/performance-efficiency) |
| [Messaging Bridge](/cloud/cloud-design-patterns/messaging/messaging-bridge) ★ | O Messaging Bridge conecta sistemas que usam infraestruturas de mensageria diferentes (por exemplo, um broker legado on-premises e um serviço de filas na nuvem) e repassa mensagens entre elas. | [`Cost Optimization`](/tags/cost-optimization) [`Operational Excellence`](/tags/operational-excellence) |
| [Message Bus](/architecture/eip/messaging-channels/message-bus) | O Message Bus é uma arquitetura de integração em que várias aplicações existentes, heterogêneas, cooperam por meio de uma infraestrutura comum de mensageria, permanecendo desacopladas. | [`Operational Excellence`](/tags/operational-excellence) [`Performance Efficiency`](/tags/performance-efficiency) |

| [Resequencer](/architecture/eip/message-routing/resequencer) | O Resequencer é um filtro com estado que coleta e reordena mensagens antes de publicá-las. | [`Reliability`](/tags/reliability) |

| [Scatter-Gather](/architecture/eip/message-routing/scatter-gather) | O Scatter-Gather envia uma requisição a vários destinatários e usa um Aggregator para coletar as respostas e combiná-las em uma só. | [`Performance Efficiency`](/tags/performance-efficiency) [`Reliability`](/tags/reliability) |
| [Routing Slip](/architecture/eip/message-routing/routing-slip) | O Routing Slip resolve o caso em que uma mensagem deve passar por uma sequência de etapas que não é fixa e pode variar de uma mensagem para outra. | [`Operational Excellence`](/tags/operational-excellence) [`Performance Efficiency`](/tags/performance-efficiency) |

| [Message Broker](/architecture/eip/message-routing/message-broker) | O Message Broker coloca um intermediário central entre remetentes e receptores. | [`Operational Excellence`](/tags/operational-excellence) [`Performance Efficiency`](/tags/performance-efficiency) |

## Message Transformation (7) {#message-transformation}

| Padrão | Resumo | Etiquetas |
| --- | --- | --- |
| [Message Translator](/architecture/eip/message-transformation/message-translator) | O Message Translator é um componente (um filtro no estilo Pipes and Filters) colocado entre dois participantes de uma integração para converter o formato de uma mensagem em outro. | [`Operational Excellence`](/tags/operational-excellence) [`Performance Efficiency`](/tags/performance-efficiency) |
| [Envelope Wrapper](/architecture/eip/message-transformation/envelope-wrapper) | O Envelope Wrapper envolve os dados de uma aplicação em um "envelope" que atende aos requisitos da infraestrutura de mensageria e, no destino, remove esse envelope para devolver os dados originais. | [`Security`](/tags/security) [`Operational Excellence`](/tags/operational-excellence) |
| [Content Enricher](/architecture/eip/message-transformation/content-enricher) | O Content Enricher é um transformador especializado que completa uma mensagem com dados que o destinatário precisa e que o remetente não enviou. | [`Operational Excellence`](/tags/operational-excellence) [`Performance Efficiency`](/tags/performance-efficiency) |
| [Content Filter](/architecture/eip/message-transformation/content-filter) | O Content Filter remove de uma mensagem os campos que o destinatário não precisa, entregando uma versão mais simples e enxuta. | [`Security`](/tags/security) [`Performance Efficiency`](/tags/performance-efficiency) |
| [Claim Check](/cloud/cloud-design-patterns/messaging/claim-check) ★ | O padrão Claim Check separa o armazenamento do conteúdo (payload) da entrega da mensagem. | [`Reliability`](/tags/reliability) [`Security`](/tags/security) [`Cost Optimization`](/tags/cost-optimization) [`Performance Efficiency`](/tags/performance-efficiency) |
| [Normalizer](/architecture/eip/message-transformation/normalizer) | O Normalizer processa mensagens semanticamente equivalentes que chegam em formatos diferentes e as converte para um único formato comum. | [`Operational Excellence`](/tags/operational-excellence) [`Reliability`](/tags/reliability) |
| [Canonical Data Model](/architecture/eip/message-transformation/canonical-data-model) | O Canonical Data Model define um formato de dados comum, independente de qualquer aplicação, que passa a ser a "língua franca" da integração. | [`Operational Excellence`](/tags/operational-excellence) [`Reliability`](/tags/reliability) |

| [Message Dispatcher](/architecture/eip/messaging-endpoints/message-dispatcher) | Message Dispatcher coordena vários consumidores de um mesmo canal. | [`Performance Efficiency`](/tags/performance-efficiency) [`Reliability`](/tags/reliability) |
| [Selective Consumer](/architecture/eip/messaging-endpoints/selective-consumer) | Selective Consumer é um consumidor que filtra as mensagens do canal e aceita somente as que atendem a seus critérios. | [`Performance Efficiency`](/tags/performance-efficiency) [`Cost Optimization`](/tags/cost-optimization) |
| [Durable Subscriber](/architecture/eip/messaging-endpoints/durable-subscriber) | Durable Subscriber é um assinante de um Publish-Subscribe Channel cuja assinatura sobrevive à sua desconexão. | [`Reliability`](/tags/reliability) |
| [Idempotent Receiver](/cloud/cloud-design-patterns/messaging/idempotent-consumer) ★ | O padrão Idempotent Consumer projeta consumidores de mensagens de forma que processar a mesma mensagem mais de uma vez produza exatamente o mesmo efeito que processá-la uma única vez. | [`Reliability`](/tags/reliability) |
| [Service Activator](/architecture/eip/messaging-endpoints/service-activator) | Service Activator fica entre o canal de mensageria e um serviço da aplicação. | [`Operational Excellence`](/tags/operational-excellence) [`Reliability`](/tags/reliability) |
