# Enterprise Integration Patterns

Personal catalog based on the [Messaging Patterns](https://www.enterpriseintegrationpatterns.com/patterns/messaging/) from Gregor Hohpe and Bobby Woolf's Enterprise Integration Patterns site, which summarizes the *Enterprise Integration Patterns* book (2003). The site's Conversation Patterns are out of scope. Each pattern has a description, the problems it solves, when to use it, trade-offs, tags (Well-Architected Framework pillars), and a Mermaid diagram.

Patterns marked with ★ are shared with another catalog: this catalog points to the original document, revised with content from this source.

Total: 65 patterns in 7 groups. Tags: Well-Architected Framework pillars.

| [Point-to-Point Channel](/architecture/eip/messaging-channels/point-to-point-channel) | The Point-to-Point Channel guarantees that each message sent is consumed by exactly one receiver. | [`Reliability`](/tags/reliability) [`Performance Efficiency`](/tags/performance-efficiency) |

| --- | --- | --- |
| [Pipes and Filters](/cloud/cloud-design-patterns/messaging/pipes-and-filters) ★ | The Pipes and Filters pattern breaks a complex processing task down into a sequence of independent, reusable steps. | [`Reliability`](/tags/reliability) |
| [Message Router](/architecture/eip/message-routing/message-router) | The Message Router is a special kind of filter that sits between message channels. | [`Operational Excellence`](/tags/operational-excellence) [`Performance Efficiency`](/tags/performance-efficiency) |

| [Aggregator](/architecture/eip/message-routing/aggregator) | The Aggregator is a stateful filter that sits between the incoming message flow and the next step. | [`Reliability`](/tags/reliability) [`Performance Efficiency`](/tags/performance-efficiency) |
| [Resequencer](/architecture/eip/message-routing/resequencer) | The Resequencer is a stateful filter that collects and reorders messages before publishing them. | [`Reliability`](/tags/reliability) |
| [Composed Message Processor](/architecture/eip/message-routing/composed-message-processor) | The Composed Message Processor handles a composite message: it splits it into submessages, sends each one to the appropriate destination, and then merges the responses into a single message. | [`Performance Efficiency`](/tags/performance-efficiency) [`Operational Excellence`](/tags/operational-excellence) |
| [Scatter-Gather](/architecture/eip/message-routing/scatter-gather) | Scatter-Gather sends a request to several recipients and uses an Aggregator to collect the responses and combine them into one. | [`Performance Efficiency`](/tags/performance-efficiency) [`Reliability`](/tags/reliability) |
| [Routing Slip](/architecture/eip/message-routing/routing-slip) | The Routing Slip solves the case where a message must go through a sequence of steps that isn't fixed and can vary from one message to another. | [`Operational Excellence`](/tags/operational-excellence) [`Performance Efficiency`](/tags/performance-efficiency) |
| [Process Manager](/architecture/eip/message-routing/process-manager) | The Process Manager is a central coordinator that maintains the state of a sequence of steps and decides the next step based on the results so far. | [`Reliability`](/tags/reliability) [`Operational Excellence`](/tags/operational-excellence) |
| [Message Broker](/architecture/eip/message-routing/message-broker) | The Message Broker puts a central intermediary between senders and receivers. | [`Operational Excellence`](/tags/operational-excellence) [`Performance Efficiency`](/tags/performance-efficiency) |

| --- | --- | --- |
| [Message Translator](/architecture/eip/message-transformation/message-translator) | The Message Translator is a component (a filter in the Pipes and Filters style) placed between two participants of an integration to convert the format of one message into another. | [`Operational Excellence`](/tags/operational-excellence) [`Performance Efficiency`](/tags/performance-efficiency) |

| [Content Enricher](/architecture/eip/message-transformation/content-enricher) | The Content Enricher is a specialized transformer that completes a message with data the recipient needs and the sender didn't send. | [`Operational Excellence`](/tags/operational-excellence) [`Performance Efficiency`](/tags/performance-efficiency) |
| [Content Filter](/architecture/eip/message-transformation/content-filter) | The Content Filter removes from a message the fields the recipient doesn't need, delivering a simpler, leaner version. | [`Security`](/tags/security) [`Performance Efficiency`](/tags/performance-efficiency) |
| [Claim Check](/cloud/cloud-design-patterns/messaging/claim-check) ★ | The Claim Check pattern separates payload storage from message delivery. | [`Reliability`](/tags/reliability) [`Security`](/tags/security) [`Cost Optimization`](/tags/cost-optimization) [`Performance Efficiency`](/tags/performance-efficiency) |
| [Normalizer](/architecture/eip/message-transformation/normalizer) | The Normalizer processes semantically equivalent messages that arrive in different formats and converts them to a single common format. | [`Operational Excellence`](/tags/operational-excellence) [`Reliability`](/tags/reliability) |
| [Canonical Data Model](/architecture/eip/message-transformation/canonical-data-model) | The Canonical Data Model defines a common data format, independent of any application, that becomes the *lingua franca* of the integration. | [`Operational Excellence`](/tags/operational-excellence) [`Reliability`](/tags/reliability) |

| [Durable Subscriber](/architecture/eip/messaging-endpoints/durable-subscriber) | Durable Subscriber is a subscriber to a Publish-Subscribe Channel whose subscription survives its disconnection. | [`Reliability`](/tags/reliability) |
| [Idempotent Receiver](/cloud/cloud-design-patterns/messaging/idempotent-consumer) ★ | The Idempotent Consumer pattern designs message consumers so that processing the same message more than once has exactly the same effect as processing it a single time. | [`Reliability`](/tags/reliability) |
| [Service Activator](/architecture/eip/messaging-endpoints/service-activator) | Service Activator sits between the messaging channel and an application service. | [`Operational Excellence`](/tags/operational-excellence) [`Reliability`](/tags/reliability) |
